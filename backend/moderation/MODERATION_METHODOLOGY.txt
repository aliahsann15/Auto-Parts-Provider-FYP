1. MODERATION METHOD / APPROACH
================================================================================

METHOD USED: Rule-Based PII Detection using Regex Pattern Matching

This system uses REGULAR EXPRESSIONS (Regex) for detecting Personal Identifiable 
Information (PII) and location-sharing intent in chat messages. No AI or machine 
learning is involved - it is purely deterministic pattern matching.

WHY REGEX?
----------
✓ Fast execution (microseconds per message)
✓ Deterministic results (same input = same output)
✓ No training data required
✓ Transparent and auditable
✓ Lightweight (minimal memory/CPU usage)
✓ Compatible with Python 3.14 (no ML library dependencies)
✓ Easy to update and extend patterns

WHAT IT DOES:
-------------
1. Receives chat message text
2. Applies predefined regex patterns (not ML-based)
3. Checks against multiple PII categories
4. Returns decision: ALLOW or BLOCK with reason
5. Zero machine learning involved - purely deterministic rule-based

2. THEORETICAL FOUNDATION
================================================================================

FORMAL LANGUAGE THEORY:
-----------------------
Regex is based on FINITE STATE AUTOMATA (FSA) and FORMAL LANGUAGE THEORY.
Each pattern represents a finite state machine that recognizes specific text patterns.

PATTERN MATCHING ALGORITHM:
---------------------------
- Uses DFA (Deterministic Finite Automaton) for pattern matching
- Time Complexity: O(n) where n = message length
- Space Complexity: O(1) for pattern storage

BOOLEAN LOGIC:
--------------
Combines multiple pattern matches using OR logic:
    BLOCK IF (pattern1 OR pattern2 OR pattern3 OR ... patternN) MATCHES
    ALLOW IF NO patterns match

SHORT-CIRCUIT EVALUATION:
-------------------------
Returns immediately when first blocking pattern is found (optimization).

3. DETECTION CATEGORIES & PATTERNS
================================================================================

A. PHONE NUMBER DETECTION
--------------------------
Patterns:
- Pakistani format: +92 or 03XX XXX XXXX
- US format: XXX-XXX-XXXX
- Generic: 10 or 11 consecutive digits

Regex Used:
    \b(?:\+92|0)?3\d{2}\s?\d{3}\s?\d{4}\b
    \b\d{3}[-.\s]?\d{3}[-.\s]?\d{4}\b
    \b\d{10,11}\b


B. EMAIL DETECTION
------------------
Standard email pattern with TLD validation

Regex Used:
    \b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b


C. PHYSICAL ADDRESS DETECTION
------------------------------
Detects:
- English keywords: home, house, apartment, street, road, building
- Urdu/Roman Urdu: ghar, dukaan, shop, gali, mohalla
- Pakistani cities: Karachi, Lahore, Islamabad, Rawalpindi, etc.
- Markets/bazaars: ganj, bazar, market, chowk, anarkali, clifton
- Directional cues: left, right, turn, near, murna, side
- Ordinal indicators: first, second, third, pehla, doosra, tesri
- Entry descriptors: gate, entrance, darvaza, hotay, enter

Regex Examples:
    \b(?:ganj|bazar|market|chowk)\b
    \b(?:left|right|turn|murna)\b
    \b(?:pehla|doosra|tesri|tisra)\b


D. CONTACT INTENT DETECTION
----------------------------
Roman Urdu keywords for direct contact:
- whatsapp, watsapp, watsup
- call karo, call krna, phone karo
- contact, direct msg, SMS

Regex Used:
    \b(?:whatsapp|call\s?karo|contact|sms)\b


E. NAME SHARING DETECTION
--------------------------
Detects explicit name introduction patterns:
- "my name is [Name]"
- "naam hai [Name]"
- "contact [Name]"

Regex Used:
    \b(?:my\s+name\s+is|naam\s+hai)\s+([A-Z][a-z]+)\b


F. PRICE NEGOTIATION (ALLOWED)
-------------------------------
Explicitly allows business-related terms:
- price, cost, rate, offer, discount, bid
- Currency: PKR, rupees, Rs

Regex Used:
    \b(?:price|cost|rate|offer|discount|rupees|pkr)\b

4. SYSTEM ARCHITECTURE
================================================================================

COMPONENTS:
-----------
1. FastAPI Service (main.py) - REST API endpoint
2. Moderation Engine (moderation_engine.py) - Core logic
3. Node.js Backend (chatController.ts) - Integration layer
4. React Frontend (buyer-chat.tsx, seller/messages) - UI

FLOW:
-----
    User Types Message
          ↓
    Frontend → POST /api/chats/:requestId
          ↓
    Backend chatController.ts
          ↓
    HTTP Request → Python Moderation Service (Port 8000)
          ↓
    Regex Pattern Matching
          ↓
    Response: {allowed: boolean, reason: string}
          ↓
    If BLOCKED → Return 400 error to frontend
    If ALLOWED → Save to MongoDB + WebSocket broadcast


API ENDPOINT:
-------------
POST http://localhost:8000/moderate
Body: {"text": "message to check"}
Response: {"allowed": true/false, "reason": "block_reason"}

================================================================================

SPEED:
------

SCALABILITY:

- No database required
- Horizontal scaling via load balancer

ACCURACY:
---------

- Best for: Explicit PII sharing
- Limitation: Creative obfuscation (e.g., "zero three double zero...")

6. ALTERNATIVE APPROACHES & COMPARISON
================================================================================

ALTERNATIVE 1: MACHINE LEARNING (NLP Models)
---------------------------------------------
Examples: BERT, GPT, spaCy NER, Presidio with ML

Pros:
+ Higher accuracy for context-based detection
+ Can learn new patterns from data
+ Better at handling variations and obfuscation
+ Named Entity Recognition (NER) for person names

Cons:
- Requires training data (thousands of labeled messages)
- Higher latency (100-500ms per message)
- Large memory footprint (500MB-2GB for models)
- Requires GPU for optimal performance
- Complex deployment and versioning
- Black box (hard to explain why blocked)
- Not compatible with Python 3.14 yet (spaCy/Presidio issues)

Cost: $$$

ALTERNATIVE 2: NLP-BASED (Named Entity Recognition - NER)
-----------------------------------------------------------
Examples: spaCy NER, BERT, Hugging Face transformer models
Approach: Machine learning-based automatic entity detection

Pros:
+ Better understanding of context (\"meet\" location vs. business)
+ Automatic detection without hardcoding keywords
+ Works with variations and creative spellings
+ Language-agnostic learning

Cons:
- Requires labeled training data (1000+ examples)
- Higher latency (100-500ms per message)
- Large memory footprint (500MB-2GB for models)
- Black box: hard to explain why blocked
- Not compatible with Python 3.14 (spaCy/Presidio compatibility issues)

ALTERNATIVE 4: Hybrid (Regex + NLP/ML)
----------------------------------------
Approach: Use rule-based regex for obvious PII, ML-based NER for context

Pros:
+ Best of both worlds: fast + accurate
+ Regex handles 80% (phones, emails, addresses)
+ NLP/ML handles edge cases (context-aware detection)
+ Lower ML latency due to pre-filtering
+ Explainable for 80% of cases

Cons:
- Higher complexity in implementation
- Still requires ML infrastructure and training data
- Dual maintenance (regex + ML models)
ALTERNATIVE 5: Simple Keyword Blacklist
----------------------------------------
Approach: Basic word/phrase blocking without regex patterns

Pros:
+ Simplest to implement
+ Zero latency
+ No dependencies

Cons:
- High false positives ("contact details" in product name)
- Easy to bypass with typos or variations
- Not context-aware
- Requires manual updates

Cost: $ (cheap but limited)
ALTERNATIVE 3: Hybrid (Regex + ML)
-----------------------------------
Use regex for obvious cases, ML for ambiguous ones

Pros:
+ Best of both worlds
+ Fast common case, accurate edge cases

Cons:
- Complexity in implementation
- Still requires ML infrastructure

Cost: $$


ALTERNATIVE 4: Keyword Blacklist
---------------------------------

Pros:

9. PATTERN UPDATE PROCESS
================================================================================

HOW TO ADD NEW PATTERNS:
------------------------
1. Identify new bypass case from logs
2. Add regex pattern to ADDRESS_KEYWORDS, PHONE_PATTERNS, etc.
3. Add test case to test_moderation.py
4. Run: python test_moderation.py
5. Restart moderation service

Example:
    # User said "aao mere ghar" (come to my house)
    # Add to ADDRESS_KEYWORDS:
    r'\b(?:aao|aana|aaja)\s+(?:mere|meray)\s+(?:ghar|shop)\b'

10. LIMITATIONS & KNOWN BYPASSES
================================================================================

CURRENT WEAKNESSES:
-------------------
1. Creative spelling: "ziro three double ziro" for 0300
2. Unicode obfuscation: using special characters
3. Image-based PII sharing (not checked)
4. Code words: "my number is written in stars" *300*
5. Multi-message split: "My number is" + "03001234567" (separate messages)

MITIGATION:
-----------
- User education (terms of service)
- Rate limiting on failed moderation attempts
- Report system for manual review
- Continuous pattern updates based on logs
